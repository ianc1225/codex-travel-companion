# Trip data boundaries

Keep reusable operating guidance separate from one trip's personal data.

## What belongs in the skill

- Planning sequence and research standards.
- Site information architecture and mobile UX principles.
- Validation steps for bookings, tickets, maps, stays, safety, and shared expenses.
- A generic data schema and deployment checklist.

## What belongs only in the trip project

- Names, contact details, booking references, entry codes, passport data, exact addresses, ticket files, payment records, passwords, and private photos.
- Current prices, opening hours, ticket availability, and event information.

Do not copy those values into the skill instructions, templates, or examples. Keep only the minimum necessary private data in a password-protected project and avoid exposing it in public links, browser logs, screenshots, or source control.

## Access and publishing

Explain what access protection does and does not protect. A shared password allows everyone who knows it to view the protected content. Do not claim that a static website supports shared edits unless it has a verified server-side storage path.
